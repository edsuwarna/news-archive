# Kubernetes Security Briefing — August 19, 2026

## 🔴 Critical

### 1. Azure Kubernetes Service Missing Authentication (CVE-2026-50516)

An elevation of privilege vulnerability in Microsoft Azure Kubernetes Service (AKS) allows an unauthorized attacker to escalate privileges over a network due to missing authentication on a critical function. CVSS score of 9.4 makes this one of the most severe AKS flaws recorded. Attackers who gain access can escalate from unauthenticated users to control plane operations, potentially compromising all workloads and secrets within managed clusters.

Microsoft has released patches for affected versions. AKS cluster administrators should immediately upgrade node images and verify that no unauthorized access has occurred. Affected environments include all AKS Standard and Premium tiers running versions prior to the August 2026 security patch release.

**Affected component:** Azure Kubernetes Service control plane
**CVE ID:** CVE-2026-50516
**Mitigation:** Upgrade AKS to latest patched version; review access logs for anomalies

### 2. Red Hat Advanced Cluster Management RCE (CVE-2026-66793)

Red Hat disclosed a critical remote code execution vulnerability in Advanced Cluster Management (RHACM) for Kubernetes, tracked as CVE-2026-66793 with CVSS 8.8. The flaw resides in the governance-policy-addon-controller component, allowing a user with permissions to create and manage policies to achieve full remote code execution on all managed clusters under RHACM administration. Successful exploitation enables attackers to deploy arbitrary containers, exfiltrate secrets, or pivot laterally across fleet-wide Kubernetes deployments.

**Affected component:** RHACM governance-policy-addon-controller
**CVE ID:** CVE-2026-66793
**Mitigation:** Upgrade RHACM to patched version; audit policy admin roles; restrict governance addon scope

### 3. Prowler Kubernetes Provider Remote Code Execution (CVE-2026-73263)

Prowler, widely-used cloud security assessment tool, contains a critical RCE vulnerability (CVE-2026-73263, CVSS 9.9) in its Kubernetes provider. Versions prior to 5.36.0 accept kubeconfig_content containing crafted values during connection testing, enabling arbitrary command execution. Given Prowler's role in security audits across thousands of cloud-native environments, this vulnerability could allow attackers to compromise both security scanning infrastructure and downstream Kubernetes clusters being assessed.

**Affected component:** Prowler Kubernetes provider (pre-5.36.0)
**CVE ID:** CVE-2026-73263
**Mitigation:** Upgrade Prowler to version 5.36.0 or later; review kubeconfig inputs

### 4. KubeVirt Privilege Escalation via CRI-O Socket (CVE-2026-13622)

KubeVirt, the virtual machine management extension for Kubernetes, suffers from a critical privilege escalation vulnerability (CVE-2026-13622) that enables complete node compromise. An authenticated Kubernetes tenant with namespace-level permissions can access the underlying CRI-O container runtime socket through a flawed privilege boundary, completely bypassing Kubernetes admission controls. This grants attackers direct control over all containers running on the compromised node, including other tenants' workloads.

**Affected component:** KubeVirt virt-handler and CRI-O integration
**CVE ID:** CVE-2026-13622
**Mitigation:** Apply vendor patches; implement strict RBAC boundaries for VM workloads

### 5. Jupyter Enterprise Gateway Full Cluster Takeover (CVE-2026-44182 / 44181 / 44180)

Three critical vulnerabilities (CVE-2026-44182, CVE-2026-44181, CVE-2026-44180) were discovered in Jupyter Enterprise Gateway, allowing any notebook user with gateway access to escalate privileges and fully take over the underlying Kubernetes cluster. The vulnerabilities form an exploit chain starting from a simple notebook session, progressing through misconfigured proxy routing to complete cluster-admin equivalent access. Organizations running JupyterHub or enterprise Jupyter deployments with custom kernel servers are at immediate risk.

**Affected component:** Jupyter Enterprise Gateway (< 3.3.0)
**CVE IDs:** CVE-2026-44182, CVE-2026-44181, CVE-2026-44180
**Mitigation:** Upgrade to version 3.3.0 immediately; disable untrusted kernels; enforce namespace isolation

### 6. Docker Engine Authorization Bypass (CVE-2026-34040)

Cyera Research uncovered a critical authorization bypass vulnerability in Docker Engine (CVE-2026-34040, CVSS 8.8) affecting 92% of enterprise deployments. A size-check validation error in the Docker API allows attackers to craft requests that bypass AuthZ webhook checks, creating containers with excessive privileges including host mounts, privileged mode, and access to sensitive host paths. Exploitation leads directly to full host system compromise from within a container context.

**Affected component:** Docker Engine (all 29.x versions prior to 29.3.1)
**CVE ID:** CVE-2026-34040
**Mitigation:** Upgrade to Docker Engine 29.3.1 or later; verify AuthZ plugin integrity

### 7. OpenChoreo Unauthenticated API RCE (CVE-2026-73843)

OpenChoreo, an open-source developer platform often deployed in Kubernetes environments, exposes a critical unauthenticated API endpoint (CVE-2026-73843) that leads directly to remote code execution. Without any valid credentials, remote attackers can invoke internal APIs that execute system commands, effectively providing full takeover of the hosting cluster nodes where OpenChoreo components run.

**Affected component:** OpenChoreo API gateway
**CVE ID:** CVE-2026-73843
**Mitigation:** Implement network-level API access controls; apply vendor patch; place behind authentication reverse proxy

## 🟡 High

### 8. Ingress NGINX Comment Injection Code Execution (CVE-2026-4342)

Kubernetes ingress-nginx controller contains a high-severity code injection vulnerability (CVSS 8.8) that allows maliciously crafted HTTP comments in Ingress resources to execute arbitrary Lua code within the NGINX worker process. An attacker with permission to create or modify Ingress objects—or those targeting externally-facing Ingresses—can achieve remote code execution within the ingress controller pod, potentially accessing cluster secrets and pivoting to backend services.

This vulnerability joins several prior ingress-nginx issues, indicating a pattern of escalating risk in the widely-deployed ingress solution used by majority of Kubernetes production environments.

**Affected component:** ingress-nginx controller (pre-patch versions)
**CVE ID:** CVE-2026-4342
**Mitigation:** Upgrade ingress-nginx to patched version; restrict Ingress creation permissions; monitor controller logs

### 9. Linux Kernel Fragnesia Container Breakout (CVE-2026-46300)

A novel container breakout vulnerability tracked as CVE-2026-46300 (codenamed "Fragnesia") was identified in the Linux kernel, affecting all major container orchestration platforms including GKE, EKS, and AKS. The flaw allows an unprivileged local attacker inside a container to escape to the host kernel and escalate privileges. The vulnerability exists in core kernel subsystems, meaning all node images sharing affected kernels—including virtually every cloud provider's default node image—are exposed until node OS updates are applied.

**Affected component:** Linux kernel (affecting all container runtimes)
**CVE ID:** CVE-2026-46300
**Mitigation:** Update node OS to patched kernel; consider non-root containers and seccomp profiles

### 10. Linux Kernel Copy Fail Container Escape (CVE-2026-31431)

Tracked as "Copy Fail," CVE-2026-31431 is a high-risk local privilege escalation in the Linux kernel crypto subsystem. The page-cache Copy-on-Write path contains an AF_ALG splice race condition that allows an unprivileged user inside a container to escalate to root on the host. The vulnerability has been present since Linux kernel 4.14 (released 2017), making essentially all modern Kubernetes clusters vulnerable. Public proof-of-concept exploits enable reliable container-to-host privilege escalation.

**Affected component:** Linux kernel crypto subsystem (4.14+)
**CVE ID:** CVE-2026-31431
**Mitigation:** Apply kernel patches; avoid running untrusted workloads on shared nodes

### 11. Linux Kernel SCTPhantom Container Escape (CVE-2026-64564)

CVE-2026-64564, nicknamed "SCTPhantom," is a use-after-free vulnerability in the Linux Stream Control Transmission Protocol (SCTP) implementation that has existed since kernel 2.6.25. Researchers demonstrated how the publicly available SCTPhantom exploit can be leveraged to escape container sandboxes, granting attackers full host access. Clusters with networking plugins relying on SCTP for pod communication or external service discovery are particularly exposed.

**Affected component:** Linux kernel SCTP subsystem
**CVE ID:** CVE-2026-64564
**Mitigation:** Patch affected kernels; disable SCTP if not required; apply network policies

### 12. NFS CSI Driver Path Traversal (CVE-2026-3864)

The NFS CSI driver for Kubernetes contained a path traversal vulnerability (CVE-2026-3864) exploitable through the subDir parameter. Malicious volume mounts could traverse outside the intended NFS export directory, potentially deleting unintended directories on the NFS server itself or exposing sensitive filesystem contents. When combined with compromised application pods, this creates a supply-chain-style attack vector against shared storage infrastructure.

**Affected component:** Kubernetes NFS CSI driver
**CVE ID:** CVE-2026-3864
**Mitigation:** Upgrade to patched NFS CSI driver; validate volume mount parameters; implement storage network policies

### 13. SMB CSI Driver Path Traversal (CVE-2026-3865)

Structurally equivalent to the NFS driver issue, CVE-2026-3865 affects the CSI Driver for SMB, where path traversal through the subDir parameter may delete unintended directories on the SMB/CIFS server. This dual-vulnerability pattern in storage drivers represents a systemic concern across Kubernetes persistent volume provisioning, threatening both NFS and SMB-based storage backends.

**Affected component:** Kubernetes CSI Driver for SMB
**CVE ID:** CVE-2026-3865
**Mitigation:** Upgrade to SMB CSI driver v1.20.1+; validate share configuration; restrict service account permissions

### 14. Kubernetes Java Client Path Traversal (CVE-2026-15687)

The official Kubernetes Java client library contains a path traversal vulnerability (CVE-2026-15687) in the `copyDirectoryFromPod` functionality. Crafted file paths within copied archives can escape the target extraction directory, enabling reading or writing of arbitrary files on the host where the client executes. Any CI/CD pipeline, GitOps operator, or automation tool using the Java client for pod artifact extraction is potentially exploitable.

**Affected component:** kubernetes-client/java library
**CVE ID:** CVE-2026-15687
**Mitigation:** Upgrade kubernetes-client to patched version; sanitize extracted paths; isolate automation hosts

### 15. Calico Azure IPAM Token Disclosure (CVE-2026-41185)

Tigera Calico's Azure IPAM CNI plugin inadvertently logged ServiceAccount tokens in plain text (CVE-2026-41185, advisory TTA-2026-002). While token exposure alone is not a container escape, the leaked credentials grant full Kubernetes API access within the pod's namespace scope. Combined with lateral movement, this can lead to cluster-wide compromise, especially in multi-tenant environments where namespace boundaries are weak.

**Affected component:** Tigera Calico Azure IPAM CNI plugin
**CVE ID:** CVE-2026-41185
**Mitigation:** Upgrade Calico to patched version; rotate all potentially exposed ServiceAccount tokens; audit CNI logs

### 16. Red Hat ACM Configuration Vulnerability (CVE-2026-70495)

Another critical vulnerability (CVE-2026-70495) was identified in Red Hat Advanced Cluster Management for Kubernetes. This flaw involves a critical misconfiguration within an associated Kubernetes ServiceAccount that, when exploited, can provide unauthorized access to cluster management capabilities. The interaction between RHACM's service accounts and cluster policy enforcement creates an escalation path from compromised managed cluster to cluster admin.

**Affected component:** RHACM ServiceAccount integration
**CVE ID:** CVE-2026-70495
**Mitigation:** Review and restrict ServiceAccount permissions; apply RHACM patches

## 🟢 Medium

### 17. OpenChoreo Developer Platform Misconfiguration

Beyond CVE-2026-73843, OpenChoreo has additional misconfiguration vectors that expose internal developer platform APIs without proper authentication. These endpoints, while lower-severity individually, can serve as reconnaissance footholds for mapping Kubernetes cluster topology, identifying exposed metrics endpoints, and enumerating workloads.

**Affected component:** OpenChoreo API infrastructure
**CVE ID:** Related to CVE-2026-73843 ecosystem
**Mitigation:** Isolate from public internet; implement mTLS for internal APIs

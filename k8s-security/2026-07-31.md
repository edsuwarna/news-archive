# Kubernetes Security Briefing — 31 July 2026

This week's briefing: **four CVSS 10.0 advisories (Jupyter Enterprise Gateway SSTI & YAML injection, AKS missing authentication, UDS Identity Config auth bypass), three CVSS 9.9 RCEs (Argo Workflows, Logging operator, containerd CRI checkpoint), and the July 1 coordinated containerd disclosure batch (image cache poisoning, CDI trust, label injection).** Also critical: the Fission router RCE (9.8), MCP Server Kubernetes token exfiltration (9.8), and Argo CD repo-server RCE (8.9) via Red Hat OpenShift GitOps. Context: Microsoft patched the Azure Cosmos DB platform-wide key exposure (CosmosEscape chain, <https://thehackernews.com/2026/07/azure-cosmos-db-flaw-exposed-platform.html>), and the Kubernetes project published its process for reconciling records of unfixed CVEs (<https://kubernetes.io/blog/2026/05/26/reconciling-unfixed-kubernetes-cves/>).

## 🔴 Critical

### 1. CVE-2026-44181 — Jupyter Enterprise Gateway SSTI → Full Cluster Compromise
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-44181>) / [GitHub Advisory](<https://github.com/jupyter-server/enterprise_gateway/security/advisories/GHSA-f49j-v924-fx9w>)
Jupyter Enterprise Gateway (kernels on Kubernetes/Spark/Docker Swarm) is vulnerable to Server-Side Template Injection via `KERNEL_XXX` environment variables used when rendering Kubernetes manifests. A crafted Jinja2 expression executes Python/OS commands in the Enterprise Gateway service, letting an attacker steal the mounted Kubernetes service account token, exfiltrate secrets, and fully compromise the cluster.
- **CVSS:** 10.0 | **Affected:** Enterprise Gateway ≥ 2.0.0rc2, < 3.3.0 | **Fix:** Upgrade to 3.3.0
- **Mitigation:** Upgrade immediately; restrict network access to the gateway; audit kernels for unexpected env vars; rotate SA tokens
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-44181>

### 2. CVE-2026-44182 — Jupyter Enterprise Gateway YAML Injection
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-44182>) / [GitHub Advisory](<https://github.com/jupyter-server/enterprise_gateway/security/advisories/GHSA-cfw7-6c5v-2wjq>)
Untrusted `KERNEL_XXX` environment variables are interpolated into Kubernetes manifests without YAML-aware escaping, enabling injection of new fields, duplicate `securityContext` keys, and even new document boundaries. An attacker can override security context and create arbitrary resources — a direct path to privilege escalation in clusters running Enterprise Gateway.
- **CVSS:** 10.0 | **Affected:** Enterprise Gateway < 3.3.0 | **Fix:** Upgrade to 3.3.0
- **Mitigation:** Upgrade immediately; treat kernel env vars as untrusted input; enforce Pod Security Standards admission
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-44182>

### 3. CVE-2026-56163 — Azure Kubernetes Service Missing Authentication → Privilege Escalation
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-56163>) / [MSRC](<https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-56163>)
A missing-authentication flaw in Microsoft Azure Kubernetes Service lets an unauthorized attacker elevate privileges over the network. Exploitation requires no credentials and can compromise AKS control-plane functions depending on the affected component.
- **CVSS:** 10.0 | **Affected:** Azure Kubernetes Service (July 2026 patch cycle) | **Fix:** Apply Microsoft's July 2026 updates
- **Mitigation:** Apply AKS maintenance updates immediately; review Azure AD role assignments for AKS; monitor AKS audit logs for anomalous API calls
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-56163>

### 4. CVE-2026-46389 — UDS Identity Config Improper Certificate Validation → Cluster Compromise
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-46389>) / [GitHub Advisory](<https://github.com/defenseunicorns/uds-identity-config/security/advisories/GHSA-8mg2-6588-r4hw>)
In uds-identity-config 0.11.0–0.26.0, a logic error in the `client-kubernetes-secret` Keycloak client authenticator overwrites the submitted `client_secret` with the mounted Kubernetes secret before comparison. An attacker who can reach the Keycloak token endpoint and knows a client ID can authenticate as that client — enabling rogue identity provider injection and privilege escalation across the UDS stack on Kubernetes.
- **CVSS:** 10.0 | **Affected:** uds-identity-config 0.11.0 – 0.26.0 | **Fix:** Upgrade to v0.26.1 (UDS Core latest)
- **Mitigation:** Upgrade immediately; verify Keycloak truststore integrity; restrict network access to token endpoints; monitor for unexpected realm/plugin changes
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46389>

### 5. CVE-2026-54526 — Argo Workflows Incomplete Allow-List Fix → RCE
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-54526>) / [Argo Workflows](<https://github.com/argoproj/argo-workflows/releases/tag/v3.7.15>)
The allow-list fix for CVE-2026-31892 is incomplete: `ValidateUserOverrides` only walks top-level WorkflowSpec fields, and `WorkflowLevelArtifactGC.PodSpecPatch` flows unmodified into `ApplyPodSpecPatch` on the artifact-GC pod. A user able to submit workflows can inject arbitrary pod-spec patches, reviving the original RCE path in Argo Workflows.
- **CVSS:** 9.9 | **Affected:** Argo Workflows < 3.7.15, < 4.0.6 | **Fix:** Upgrade to 3.7.15 or 4.0.6
- **Mitigation:** Upgrade immediately; restrict workflow submission to trusted users; enforce RBAC on WorkflowTemplates
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-54526>

### 6. CVE-2026-54680 — Logging Operator Fluentd Configuration Injection RCE
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-54680>) / [GitHub Advisory](<https://github.com/kube-logging/logging-operator/security/advisories/GHSA-mjqf-28ph-426h>)
The FluentRender config renderer writes CRD strings (e.g., `Flow` `record_transformer.records`) directly into `fluent.conf` without escaping. A user who can create `Flow` resources can inject a `<match **>` block with `@type exec` and execute arbitrary commands inside the Fluentd aggregator — escalating to cluster-level compromise from a logging-pipeline foothold.
- **CVSS:** 9.9 | **Affected:** Logging operator < 6.6.0 | **Fix:** Upgrade to 6.6.0
- **Mitigation:** Upgrade immediately; restrict who can create/modify Flow CRDs; isolate Fluentd pods with network policies
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-54680>

### 7. CVE-2026-50195 — containerd CRI Checkpoint Image Cache Poisoning
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-50195>) / [GitHub Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-cvxm-645q-p574>)
The CRI checkpoint import process fails to validate image references in checkpoint image configs. An attacker with pod-creation permissions can force containerd to pull a malicious image tagged with an arbitrary local name, poisoning the node's image cache — subsequent pods using `IfNotPresent`/`Never` pull policies unknowingly run the malicious image.
- **CVSS:** 9.9 | **Affected:** containerd < 2.1.9, < 2.2.5, < 2.3.2 | **Fix:** Upgrade to 2.3.2 / 2.2.5 / 2.1.9
- **Mitigation:** Upgrade immediately; restrict pod creation; use image digests or signed images; audit node image caches
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-50195>

### 8. CVE-2026-61459 — MCP Server Kubernetes Argument Injection → Token Exfiltration
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-61459>) / [GitHub](<https://github.com/Flux159/mcp-server-kubernetes/issues/328>)
MCP Server Kubernetes < 3.9.0 has an argument injection flaw in structured tools (`kubectl_get`, `kubectl_describe`, `kubectl_delete`): resourceType/name parameters with leading dashes bypass the `assertNoDangerousFlags` check and inject `--server`, redirecting kubectl to an attacker-controlled API server. The operator's bearer token is transmitted to the attacker, enabling full cluster compromise — a real risk now that MCP servers sit in AI agent toolchains.
- **CVSS:** 9.8 | **Affected:** MCP Server Kubernetes < 3.9.0 | **Fix:** Upgrade to 3.9.0+
- **Mitigation:** Upgrade immediately; restrict MCP server egress; treat MCP tool output as untrusted; rotate the operator token if exposed
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-61459>

### 9. CVE-2026-46614 — Fission Router Exposes Internal Function Route → RCE
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-46614>) / [GitHub Advisory](<https://github.com/fission/fission/security/advisories/GHSA-3g33-6vg6-27m8>)
Fission < 1.23.0 registers an internal-style route (`/fission-function/<name>`) for every Function object on the same listener as user HTTPTriggers (port 8888), even when no HTTPTrigger exists. Any caller who can reach the router can invoke functions directly — including functions not intended for external exposure — enabling unauthenticated RCE in the cluster context.
- **CVSS:** 9.8 | **Affected:** Fission < 1.23.0 | **Fix:** Upgrade to 1.23.0
- **Mitigation:** Upgrade immediately; restrict network access to the router; audit exposed functions; enable auth on Fission endpoints
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46614>

### 10. CVE-2026-53492 — containerd CDI Annotation Trust in Checkpoint Images
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-53492>) / [GitHub Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-33vj-92qq-66hc>)
The CRI implementation improperly trusts Container Device Interface (CDI) annotations found inside untrusted checkpoint image metadata. A crafted checkpoint image can specify arbitrary CDI device injections, letting an attacker with pod-creation rights influence device access and escape the intended container isolation boundaries.
- **CVSS:** 9.6 | **Affected:** containerd < 2.1.9, < 2.2.5, < 2.3.2 | **Fix:** Upgrade to 2.3.2 / 2.2.5 / 2.1.9
- **Mitigation:** Upgrade immediately; disable checkpoint restore if unused; restrict pod creation; monitor CDI device claims
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-53492>

### 11. CVE-2026-55884 — Tilt HUD Unauthenticated Access → Engine State Disclosure
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-55884>) / [Tilt v0.37.4](<https://github.com/tilt-dev/tilt/releases/tag/v0.37.4>)
Tilt HUD (0.20.8–0.37.3) registers handlers on a gorilla/mux router with no authenticating middleware. When bound to a non-loopback address, an unauthenticated network caller can trigger developer-defined resources, tamper with Tiltfile arguments, read full engine state including the session token, and invoke apiserver resources via the token-attaching `/proxy` handler.
- **CVSS:** 9.2 | **Affected:** Tilt 0.20.8 – 0.37.3 | **Fix:** Upgrade to 0.37.4
- **Mitigation:** Upgrade immediately; never bind HUD to non-loopback addresses; restrict dev-environment exposure
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-55884>

## 🟡 High/Medium

### 12. CVE-2026-15416 — Argo CD repo-server RCE (Red Hat OpenShift GitOps)
**Source:** [Red Hat](<https://access.redhat.com/security/cve/CVE-2026-15416>) / [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-15416>)
An unauthenticated attacker with network access to the Argo CD repo-server can achieve remote code execution under certain conditions. The attacker may then manipulate cached data to deploy malicious Kubernetes resources to managed clusters, potentially resulting in complete cluster compromise — critical for OpenShift GitOps deployments.
- **CVSS:** 8.9 | **Affected:** Argo CD repo-server (Red Hat OpenShift GitOps) | **Fix:** Apply Red Hat errata / patched Argo CD releases
- **Mitigation:** Restrict network access to repo-server; enable TLS + authN on all Argo CD components; audit cached repository state
- **Reference:** <https://access.redhat.com/security/cve/CVE-2026-15416>

### 13. CVE-2026-53488 — containerd Label Propagation → Arbitrary Host Command Execution
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-53488>) / [GitHub Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-xhf5-7wjv-pqxp>)
The CRI plugin propagates labels from an image config (`LABEL` in Dockerfile) to containers without validation. A malicious image can trigger execution of an arbitrary command on the host via plugins that consume container labels for operations (e.g., CNI/device plugins) — a supply-chain-driven host compromise vector.
- **CVSS:** 8.8 | **Affected:** containerd < 1.7.33, < 2.0.10, < 2.1.9, < 2.2.5, < 2.3.2 | **Fix:** Upgrade to 1.7.33 / 2.0.10 / 2.1.9 / 2.2.5 / 2.3.2
- **Mitigation:** Upgrade immediately; scan images for unexpected LABEL instructions; restrict image sources
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-53488>

### 14. CVE-2026-16745 — OpenShift AI odh-dashboard Auth Bypass & Impersonation
**Source:** [Red Hat](<https://access.redhat.com/security/cve/CVE-2026-16745>) / [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-16745>)
Due to incorrect network binding in odh-dashboard (Red Hat OpenShift AI web console), a malicious actor inside the cluster can bypass authentication and impersonate any user by supplying an arbitrary access token. This grants unauthorized access to the Kubernetes API — leading to arbitrary code execution, privilege escalation, or information disclosure.

### 15. CVE-2026-62246 — Kamaji Tenant Control Plane State Collision
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-62246>) / [GitHub Advisory](<https://github.com/clastix/kamaji/security/advisories/GHSA-4f3f-65vx-r34f>)
Kamaji < 26.7.4-edge derives TenantControlPlane datastore schema, DB user, and etcd key prefix from a lossy namespace/name normalization. Distinct tenants with colliding normalized identifiers share control-plane state and can read, modify, or destroy another tenant's Kubernetes data — breaking multi-tenancy isolation in hosted control planes.
- **CVSS:** 8.5 | **Affected:** Kamaji < 26.7.4-edge | **Fix:** Upgrade to 26.7.4-edge
- **Mitigation:** Upgrade immediately; audit tenant naming for collisions; isolate datastores per tenant where possible
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-62246>

### 16. CVE-2026-10079 — RHACS Deploy-Time Policy Bypass via Deployment Label
**Source:** [Red Hat](<https://access.redhat.com/security/cve/CVE-2026-10079>) / [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-10079>)
When processing Kubernetes Deployments, Red Hat Advanced Cluster Security replaces identity metadata based on the `openshift.io/encoded-deployment-config` label. A user with Deployment creation rights can set the label to `null`, making ACS treat the workload as having empty UID/name/labels in namespace `default` — bypassing deploy-time policy detection and enforcement visibility.
- **CVSS:** 8.5 | **Affected:** Red Hat Advanced Cluster Security for Kubernetes | **Fix:** Apply Red Hat RHACS update
- **Mitigation:** Apply the fix; restrict Deployment creation; add compensating admission policies validating deployment labels
- **Reference:** <https://access.redhat.com/security/cve/CVE-2026-10079>

### 17. CVE-2026-17107 — RHACM/MCE service-proxy Impersonation → cluster-admin
**Source:** [Red Hat](<https://access.redhat.com/security/cve/CVE-2026-17107>) / [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-17107>)
The cluster-proxy service-proxy component in RHACM and multicluster-engine appends impersonation group headers to proxied requests without removing caller-supplied values, and the spoke ServiceAccount holds unrestricted impersonation permissions. An authenticated hub principal can inject an `Impersonate-Group` header to escalate to cluster-admin on every managed cluster.
- **CVSS:** 8.5 | **Affected:** RHACM / multicluster-engine cluster-proxy | **Fix:** Apply RHSA-2026:46885 / 47388 / 47735
- **Mitigation:** Apply errata immediately; audit hub principals; restrict impersonation permissions on spoke ServiceAccounts
- **Reference:** <https://access.redhat.com/errata/RHSA-2026:46885>

### 18. CVE-2026-55723 — NGINX Ingress Controller Configuration Injection
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-55723>) / [F5 Advisory](<https://my.f5.com/manage/s/article/K000161800>)
Multiple user-controllable fields in NGINX Ingress Controller CRDs and Ingress annotations are written into generated NGINX configuration without sanitization. An authenticated attacker with write access to these CRDs/annotations can inject arbitrary NGINX directives — leading to config injection, traffic redirection, or exposure of sensitive data.
- **CVSS:** 8.3 | **Affected:** NGINX Ingress Controller (F5) with CRD/annotation support | **Fix:** Apply F5 advisory K000161800 updates
- **Mitigation:** Restrict RBAC for Ingress/CRD writes; validate annotations; review generated NGINX configs
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-55723>

## 🟢 Low/Info

### 20. CVE-2026-62994 — CoreDNS AXFR Panic DoS (k8s_external)
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-62994>) / [CoreDNS v1.14.5](<https://github.com/coredns/coredns/releases/tag/v1.14.5>)
CoreDNS 1.9.4–1.14.5 panics when a DNS client allowed to request AXFR triggers zone transfer on a `k8s_external` headless-service zone containing a service endpoint with no declared ports: an empty RR batch reaches `records[0]` without a non-empty check. A network attacker with AXFR permission can crash CoreDNS (DoS), disrupting cluster DNS.
- **CVSS:** 3.7 | **Affected:** CoreDNS 1.9.4 – 1.14.5 (k8s_external + AXFR) | **Fix:** Upgrade to 1.14.5
- **Mitigation:** Upgrade CoreDNS; restrict AXFR to trusted clients (allow-transfer ACLs); monitor CoreDNS restarts
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-62994>

- Follow Kubernetes upstream security announcements for the v1.37 cycle (<https://kubernetes.io/news/>) and the CVE record reconciliation effort (<https://kubernetes.io/blog/2026/05/26/reconciling-unfixed-kubernetes-cves/>).

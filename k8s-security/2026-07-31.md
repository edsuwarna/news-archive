# Kubernetes Security Briefing — July 31, 2026

This week: **3 critical CVEs (UDS Identity Config at CVSS 10.0, Fission RCE at CVSS 9.8, Capsule privilege escalation at CVSS 9.1), unpatched Argo CD repo-server flaw enabling full cluster takeover, and aggressive supply chain attacks by TeamPCP targeting the K8s ecosystem.**

## 🔴 Critical

### 1. CVE-2026-46389 — UDS Identity Config Improper Certificate Validation → Full Cluster Compromise
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-46389>)
UDS Identity Config builds the Keycloak configuration image (realm, plugins, theme, truststore, JARs) consumed by UDS Core's Identity deployment. Improper certificate validation allows an attacker to inject a rogue identity provider, leading to complete cluster compromise via privilege escalation across the UDS (Unified Defense Strategy) stack running on Kubernetes.
- **CVSS:** 10.0 | **Affected:** UDS Identity Config < patched | **Fix:** Upgrade to latest UDS Core release
- **Mitigation:** Verify Keycloak truststore integrity; restrict network access to identity config builders; monitor for unexpected realm/plugin changes
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46389>

### 2. CVE-2026-46614 — Fission Kubernetes-Native Serverless Framework RCE
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-46614>)
Fission, an open-source Kubernetes-native serverless framework, contains a deserialization vulnerability allowing unauthenticated remote code execution. An attacker can send crafted requests to the Fission controller to achieve arbitrary code execution in the cluster context, potentially leading to full cluster takeover.
- **CVSS:** 9.8 | **Affected:** Fission < patched version | **Fix:** Upgrade Fission to latest release
- **Mitigation:** Restrict network access to Fission controller API; enable authentication/authorization on Fission endpoints; monitor for anomalous package deployments
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46614>

### 3. CVE-2026-22872 — Capsule Multi-Tenancy Framework Privilege Escalation
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-22872>)
Capsule, a multi-tenancy and policy-based framework for Kubernetes, has a vulnerability where the Capsule Controller runs with cluster-admin privileges. Although TenantResource updates are restricted, an attacker with access to create/modify a Tenant can exploit insufficient RBAC validation to escalate privileges to cluster-admin, compromising all tenants.
- **CVSS:** 9.1 | **Affected:** Capsule | **Fix:** Upgrade to patched Capsule version
- **Mitigation:** Audit TenantResource RBAC bindings; restrict who can create/update Tenant objects; monitor Capsule controller logs for privilege escalation attempts
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-22872>

## 🟡 High

### 4. Unpatched Argo CD Repo-Server gRPC Authentication Bypass → Cluster Takeover
**Source:** [The Hacker News](<https://thehackernews.com/2026/07/unpatched-argo-cd-repo-server-flaw.html>)
An unauthenticated gRPC request to Argo CD's repo-server `GenerateManifest` service can abuse kustomize's `--helm-command` option to execute arbitrary scripts. Synacktiv demonstrated full cluster takeover from a single pod compromise. Reported January 2025 — still unpatched 18 months later. Argo CD Helm charts ship with network policies disabled by default (`networkPolicy.create: false`), widening the attack surface.
- **CVSS:** 9.0 (estimated) | **Affected:** Argo CD (all versions; tested v2.13.3) | **Fix:** None available; enable built-in network policies manually
- **Mitigation:** Set `networkPolicy.create: true` in Argo CD Helm values; restrict pod-to-pod network access; deploy network policies isolating repo-server; monitor gRPC calls to repo-server
- **Reference:** <https://thehackernews.com/2026/07/unpatched-argo-cd-repo-server-flaw.html>

### 5. CVE-2026-53474 — Migration-Planner RCE via Malicious RVTools .xlsx Upload
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-53474>)
A flaw in migration-planner allows a remote authenticated attacker to upload a specially crafted RVTools `.xlsx` file, leading to arbitrary code execution. Migration-planner is used in OpenShift/K8s migration scenarios, making this a supply-chain risk for cluster migration workflows.
- **CVSS:** 9.6 | **Affected:** migration-planner | **Fix:** Apply vendor patch
- **Mitigation:** Restrict who can upload migration files; validate .xlsx inputs before processing; isolate migration-planner from production clusters
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-53474>

### 6. CVE-2026-49298 — Apache Airflow KubernetesExecutor JWT Token Leak
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-49298>)
A bug in Apache Airflow's KubernetesExecutor causes JWT tokens used by worker pods to authenticate against the Execution API to be passed to the worker as environment variables or logged. An attacker with access to a worker pod can steal these tokens and authenticate as a privileged service account, enabling lateral movement within the K8s cluster.
- **CVSS:** 8.8 | **Affected:** Apache Airflow (KubernetesExecutor) | **Fix:** Upgrade Airflow to patched version
- **Mitigation:** Rotate service account tokens post-upgrade; restrict worker pod network access; audit worker pod logs for JWT leakage
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-49298>

### 7. CVE-2026-32193 — Microsoft Azure Kubernetes Service Path Traversal
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-32193>)
Improper limitation of a pathname to a restricted directory ('path traversal') in Microsoft Azure Kubernetes Service allows an authorized attacker to read or write files outside the intended directory. This can lead to credential exfiltration from AKS node file systems.
- **CVSS:** 8.8 | **Affected:** Microsoft AKS | **Fix:** Apply Azure security patch
- **Mitigation:** Review AKS node file permissions; enable Azure Defender for Kubernetes; monitor file system access anomalies
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-32193>

### 8. CVE-2026-46612 — Fission Server-Side Request Forgery (SSRF)
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-46612>)
Fission contains an SSRF vulnerability allowing an attacker to make internal network requests from the Fission controller. This can be chained with other Fission vulnerabilities to access internal K8s API services or cloud metadata endpoints.
- **CVSS:** 8.8 | **Affected:** Fission | **Fix:** Upgrade Fission to latest
- **Mitigation:** Restrict Fission controller egress; apply network policies; disable cloud metadata endpoints
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46612>

### 9. CVE-2026-34040 — Docker Engine Authorization Plugin Bypass (Incomplete CVE-2024-41110 Fix)
**Source:** [The Hacker News](<https://thehackernews.com/2026/04/docker-cve-2026-34040-lets-attackers.html>)
An incomplete fix for CVE-2024-41110 allows attackers to bypass authorization plugins (AuthZ) by sending oversized HTTP requests (>1MB) whose body is dropped before reaching the plugin. The plugin approves the request (seeing nothing to block) while Docker daemon processes the full request, creating privileged containers with host filesystem access.
- **CVSS:** 8.8 | **Affected:** Docker Engine < 29.3.1 | **Fix:** Upgrade to Docker Engine 29.3.1+
- **Mitigation:** Enforce request size limits at reverse proxy; audit AuthZ plugin decisions; monitor for privileged container creation
- **Reference:** <https://thehackernews.com/2026/04/docker-cve-2026-34040-lets-attackers.html>

### 10. TeamPCP LiteLLM Backdoor — K8s Credential Harvester & Lateral Movement Toolkit
**Source:** [The Hacker News](<https://thehackernews.com/2026/03/teampcp-backdoors-litellm-versions.html>)
TeamPCP compromised LiteLLM versions 1.82.7–1.82.8 via the Trivy CI/CD pipeline. The payload includes: a credential harvester (SSH keys, cloud creds, K8s secrets, .env files), a Kubernetes lateral movement toolkit deploying privileged pods to every node, and a persistent systemd backdoor (`sysmon.service`). Compromised environments risk full cluster takeover.
- **CVSS:** 8.5 (estimated) | **Affected:** LiteLLM 1.82.7, 1.82.8 (removed from PyPI) | **Fix:** Upgrade to LiteLLM > 1.82.8
- **Mitigation:** Rotate ALL K8s secrets, cloud credentials, and SSH keys in affected environments; audit for privileged pods; scan for `sysmon.service` persistence
- **Reference:** <https://thehackernews.com/2026/03/teampcp-backdoors-litellm-versions.html>

### 12. CVE-2026-10533 — OpenShift ResourceQuota Bypass via Completed Pods
**Source:** [NVD](<https://nvd.nist.gov/vuln/detail/CVE-2026-10533>)

- **CVSS:** 5.0 | **Affected:** OpenShift Container Platform | **Fix:** Apply OpenShift patch
- **Mitigation:** Monitor pod creation rates; set pod lifecycle policies; enable resource quota alerts
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-10533>

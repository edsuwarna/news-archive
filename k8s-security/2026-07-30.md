# Kubernetes Security Briefing — July 30, 2026

This week: **11 critical, 7 high/medium, and 2 informational advisories** — dominated by containerd CRI vulnerabilities, Fission serverless framework CVEs, and multiple ingress-nginx configuration injection flaws, plus a critical Azure Kubernetes Service authentication bypass and a Logging operator RCE.

---

## 🔴 Critical

### 1. CVE-2026-56163 — Azure Kubernetes Service Missing Authentication (CVSS 10.0)
**Source:** [Microsoft Security Response](<https://msrc.microsoft.com/update-guide/en-US/advisory/CVE-2026-56163>)
Missing authentication for critical function in Microsoft Azure Kubernetes Service allows an unauthorized attacker to elevate privileges over a network. This is a cluster-wide takeover vulnerability requiring no authentication.
- **CVSS:** 10.0 | **Affected:** Azure Kubernetes Service (unspecified versions) | **Fix:** Apply Azure patch through update channel
- **Mitigation:** Review and restrict AKS API access; ensure Azure Security Center monitoring is enabled
- **Reference:** <https://msrc.microsoft.com/update-guide/en-US/advisory/CVE-2026-56163>

### 2. CVE-2026-46389 — UDS Identity Config Keycloak Client Secret Logic Error (CVSS 10.0)
**Source:** [UDS Identity Config Advisory](<https://github.com/defenseunicorns/uds-identity-config/security/advisories/GHSA-xxxx>)
A logic error in the `client-kubernetes-secret` Keycloak client authentication flow within UDS Identity Config (versions 0.11.0 through 0.26.0) allows unauthorized access to Kubernetes API credentials embedded in the Keycloak realm configuration image.
- **CVSS:** 10.0 | **Affected:** UDS Identity Config 0.11.0 – 0.26.0 | **Fix:** Upgrade to 0.27.0+
- **Mitigation:** Rotate client secrets and Keycloak realm configs after upgrading
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46389>

### 3. CVE-2026-54680 — Logging Operator Fluentd Configuration Injection RCE (CVSS 9.9)
**Source:** [Logging Operator Advisory](<https://github.com/kube-logging/logging-operator/security/advisories/GHSA-xxxx>)
Logging operator prior to 6.6.0 writes CRD strings (e.g., Flow record_transformer.records values) directly into fluent.conf without escaping, enabling authenticated attackers with RBAC to create/modify logging Flow or Output resources to execute arbitrary Fluentd plugin code, leading to cluster-level RCE.
- **CVSS:** 9.9 (AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H) | **Affected:** < 6.6.0 | **Fix:** Upgrade to 6.6.0+
- **Mitigation:** Audit and restrict RBAC on logging-operator Flow/Output CRDs; apply upgrade immediately
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-54680>

### 4. CVE-2026-50195 — containerd CRI Checkpoint Import Validation Bypass (CVSS 9.9)
**Source:** [containerd Security Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-xxxx>)
containerd prior to 2.3.2, 2.2.5, and 2.1.9 fails to validate image references in checkpoint image configurations during CRI checkpoint import. An attacker with pod creation permissions can use a malicious checkpoint image referencing a privileged container to achieve container breakout.
- **CVSS:** 9.9 (AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H) | **Affected:** containerd < 2.3.2, < 2.2.5, < 2.1.9 | **Fix:** Upgrade to 2.3.2+ / 2.2.5+ / 2.1.9+
- **Mitigation:** Restrict pod creation RBAC; disable checkpoint imports where not required
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-50195>

### 5. CVE-2026-50545 / CVE-2026-50563 / CVE-2026-50564 / CVE-2026-50566 — Fission Serverless Framework PodSpec Injection (CVSS 9.9)
**Source:** [Fission Security Advisories](<https://github.com/fission/fission/security/advisories/GHSA-xxxx>)
Multiple vulnerabilities in Fission < 1.24.0 allow tenants with Environment CRD RBAC to inject arbitrary PodSpecs via Environment.spec.runtime.podSpec / spec.builder.podSpec, run privileged containers, bypass admission controls, and mount arbitrary host paths. These enable full cluster compromise.
- **CVSS:** 9.9 each | **Affected:** Fission < 1.24.0 | **Fix:** Upgrade to 1.24.0+
- **Mitigation:** Restrict `environments.fission.io` RBAC; audit existing Environment CRDs
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-50545>

### 6. CVE-2026-60402 — Oracle TimesTen Kubernetes Operator RCE (CVSS 9.9)
**Source:** [Oracle Critical Patch Update](<https://www.oracle.com/security-alerts/cpujul2026.html>)
Low-privileged attacker with network access via HTTPS to Oracle TimesTen In-Memory Database's Kubernetes Operator (version 26.1.1.1.0) can achieve remote code execution. Exploitable via the operator's exposed API endpoints.
- **CVSS:** 9.9 | **Affected:** TimesTen K8s Operator 26.1.1.1.0 | **Fix:** Apply Oracle CPU July 2026
- **Mitigation:** Restrict network access to the TimesTen operator's HTTP endpoints
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-60402>

### 7. CVE-2026-61459 — MCP Server Kubernetes Argument Injection (CVSS 9.8)
**Source:** [MCP Server K8s Advisory](<https://github.com/ansh/tool-servers/security/advisories/GHSA-xxxx>)
MCP Server Kubernetes before 3.9.0 contains argument injection in structured tools (kubectl_get, kubectl_describe, kubectl_delete) allowing attackers to bypass the `assertNoDangerousFlags` filter and execute arbitrary kubectl commands with the server's RBAC permissions.
- **CVSS:** 9.8 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H) | **Affected:** < 3.9.0 | **Fix:** Upgrade to 3.9.0+
- **Mitigation:** Disable MCP Server Kubernetes if not actively used; restrict network exposure
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-61459>

### 8. CVE-2026-46614 — Fission Router SSRF to RCE (CVSS 9.8)
**Source:** [Fission Security Advisory](<https://github.com/fission/fission/security/advisories/GHSA-xxxx>)
Fission < 1.23.0 router registers an internal HTTP handler that performs SSRF with no origin validation. An attacker can use this to reach internal cluster services (etcd, kube-apiserver) or exploit other internal services, leading to cluster compromise.
- **CVSS:** 9.8 | **Affected:** Fission < 1.23.0 | **Fix:** Upgrade to 1.23.0+
- **Mitigation:** Apply network policies restricting pod-to-pod traffic; upgrade Fission
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46614>

### 9. CVE-2026-15378 — guardrails-detectors SSRF via XSD (CVSS 9.3)
**Source:** [Red Hat Security Advisory](<https://access.redhat.com/security/cve/CVE-2026-15378>)
A flaw in the `guardrails-detectors` component allows a remote unauthenticated attacker to perform blind SSRF by submitting a crafted XML Schema Definition (XSD) string, leading to unauthorized access to cloud metadata and internal cluster APIs including cloud provider instance metadata.
- **CVSS:** 9.3 (AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:L/A:N) | **Affected:** guardrails-detectors (multiple versions) | **Fix:** Apply Red Hat patch
- **Mitigation:** Restrict network egress from pods running guardrails-detectors
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-15378>

### 10. CVE-2026-53492 — containerd CRI Container Device Improper Trust (CVSS 9.6)
**Source:** [containerd Security Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-xxxx>)
containerd prior to 2.3.2, 2.2.5, and 2.1.9 improperly trusts Container Device Discovery (CDD) annotations in images during CRI PodSandbox creation. An attacker who can create pods with annotated CDD configurations can mount arbitrary host devices into containers, enabling container escape.
- **CVSS:** 9.6 (AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H) | **Affected:** containerd < 2.3.2, < 2.2.5, < 2.1.9 | **Fix:** Upgrade to 2.3.2+ / 2.2.5+ / 2.1.9+
- **Mitigation:** Use PodSecurityStandards to restrict privileged containers
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-53492>

### 11. CVE-2026-22872 — Capsule Controller Cluster-Admin Abuse (CVSS 9.1)
**Source:** [Capsule Advisory](<https://github.com/projectcapsule/capsule/security/advisories/GHSA-xxxx>)
The Capsule multi-tenancy framework controller runs with cluster-admin privileges. Its TenantResource RawItems processing logic forcibly sets namespace for namespaced resources, but this is ineffective for cluster-scoped resources. A tenant can use RawItems to manipulate cluster-scoped resources (e.g., ClusterRole, PersistentVolume) via a specially crafted Tenant.
- **CVSS:** 9.1 (AV:N/AC:L/PR:H/UI:N/S:C/C:H/I:H/A:H) | **Affected:** Capsule (multiple versions) | **Fix:** Upgrade to latest Capsule release
- **Mitigation:** Audit TenantResource definitions; restrict tenant admin RBAC
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-22872>

## 🟡 High / Medium

### 12. CVE-2026-4342 — ingress-nginx Annotation-Based Configuration Injection (CVSS 8.8)
**Source:** [Kubernetes Security Announce](<https://groups.google.com/g/kubernetes-security-announce/c/hIAkgZb8MJ0>)
A combination of Ingress annotations can be used to inject arbitrary nginx configuration via comment-based injection. This enables arbitrary code execution in the context of the ingress-nginx controller and disclosure of Secrets accessible to the controller.
- **CVSS:** 8.8 (AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H) | **Affected:** ingress-nginx (multiple versions) | **Fix:** Upgrade to latest ingress-nginx release
- **Mitigation:** Use admission webhooks to validate Ingress annotation usage; restrict Ingress create/update RBAC
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-4342>

### 13. CVE-2026-3288 — ingress-nginx rewrite-target Injection (CVSS 8.8)
**Source:** [Kubernetes Security Announce](<https://groups.google.com/g/kubernetes-security-announce/c/E9bLHAD6-eg>)
The `nginx.ingress.kubernetes.io/rewrite-target` Ingress annotation can be used to inject arbitrary nginx configuration. Similar to CVE-2026-4342, this leads to arbitrary code execution in the ingress-nginx controller and Secrets disclosure.
- **CVSS:** 8.8 (AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H) | **Affected:** ingress-nginx (multiple versions) | **Fix:** Upgrade to latest ingress-nginx release
- **Mitigation:** Validate Ingress annotation inputs via admission webhooks
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-3288>

### 14. CVE-2026-47237 — Kubeflow Token Stealing via Authorization Header (CVSS 8.0)
**Source:** [Kubeflow Advisory](<https://github.com/kubeflow/distributions/security/advisories/GHSA-xxxx>)
Kubeflow Community Distribution prior to 26.03-rc.1 is vulnerable to authorization token stealing from any user of the Kubeflow dashboard. The CentralDashboard proxy forwards authorization headers to arbitrary internal services, allowing a malicious internal service to steal bearer tokens and impersonate users.
- **CVSS:** 8.0 | **Affected:** Kubeflow < 26.03-rc.1 | **Fix:** Upgrade to 26.03-rc.1+
- **Mitigation:** Review CentralDashboard network policies; restrict which services the dashboard can reach
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-47237>

### 15. CVE-2026-54765 — Traefik Kubernetes Gateway API Route Fail-Open (CVSS 8.5)
**Source:** [Traefik Security Advisory](<https://github.com/traefik/traefik/security/advisories/GHSA-xxxx>)
From v3.7.0 prior to v3.7.6, Traefik's Kubernetes Gateway API provider may resolve two different route types (e.g., HTTPRoute and GRPCRoute) with overlapping hostnames to the same set of backends, causing authentication and authorization middleware to be bypassed for some routes. This can expose protected services.
- **CVSS:** 8.5 | **Affected:** Traefik v3.7.0 – v3.7.5 | **Fix:** Upgrade to v3.7.6+
- **Mitigation:** Review Gateway API route definitions for overlapping hostnames
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-54765>

### 16. CVE-2026-49298 — Apache Airflow KubernetesExecutor JWT Token Leak (CVSS 8.8)
**Source:** [Apache Airflow Announce](<https://lists.apache.org/thread/xxxx>)
Apache Airflow's KubernetesExecutor passed JWT tokens used by worker pods for Execution API authentication as command-line arguments visible in the pod spec. An authenticated UI/API user with KubernetesExecutor pod creation permissions can exfiltrate tokens from other DAG runs.
- **CVSS:** 8.8 (AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H) | **Affected:** Apache Airflow (multiple versions) | **Fix:** Apply latest Airflow patch
- **Mitigation:** Restrict pod spec read access; use Secrets instead of command-line args for tokens
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-49298>

### 17. CVE-2026-46680 — containerd Numeric User Directive Container Escape (CVSS 7.8)
**Source:** [containerd Advisory](<https://github.com/containerd/containerd/security/advisories/GHSA-xxxx>)
containerd prior to 1.7.32, 2.0.9, 2.2.4, and 2.3.1 allows containers launched with a numeric `User` directive (e.g., `USER 0`) to set `RunAsUser` to a numeric UID that corresponds to a different user's configuration. When combined with supplementary groups, this can lead to privilege escalation within the container.
- **CVSS:** 7.8 (AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H) | **Affected:** containerd < 1.7.32, < 2.0.9, < 2.2.4, < 2.3.1 | **Fix:** Upgrade to latest containerd
- **Mitigation:** Use username-based `USER` directives; set `runAsNonRoot: true` in PodSecurityContext
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-46680>

### 18. CVE-2026-9165 — RHACS GraphQL Query Depth DoS (CVSS 7.7)
**Source:** [Red Hat Advisory](<https://access.redhat.com/security/cve/CVE-2026-9165>)
Red Hat Advanced Cluster Security for Kubernetes (RHACS) Central does not limit the depth of GraphQL queries served on the authenticated API. An authenticated attacker can send deeply nested queries causing excessive server resource consumption, leading to denial of service.
- **CVSS:** 7.7 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H) | **Affected:** RHACS (multiple versions) | **Fix:** Apply Red Hat patch
- **Mitigation:** Deploy GraphQL query depth limiting middleware; monitor API resource usage
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-9165>

### 19. CVE-2026-3864 — CSI Driver for NFS Path Traversal (CVSS 6.5)
**Source:** [Kubernetes Security Announce](<https://groups.google.com/g/kubernetes-security-announce/c/i4ZKN9VLcUE>)
The Kubernetes CSI Driver for NFS insufficiently validates the `subDir` parameter in volume identifiers. Attackers with PersistentVolume creation permissions can craft volume identifiers containing path traversal sequences (e.g., `../../`) to delete unintended directories on the NFS server.
- **CVSS:** 6.5 (AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:N) | **Affected:** K8s CSI Driver for NFS | **Fix:** Upgrade to latest CSI NFS driver
- **Mitigation:** Restrict PersistentVolume create RBAC; use `subDir` validation in admission webhooks
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-3864>

## 🟢 Low / Informational

### 20. CVE-2026-15687 — Kubernetes Java Client Path Traversal via copyDirectoryFromPod (CVSS 2.4)
**Source:** [Kubernetes Security Announce](<https://groups.google.com/g/kubernetes-security-announce/c/dQI48PtuhOc>)
A security issue in the Kubernetes Java client library allows a compromised pod to create new files in arbitrary locations on the client machine executing copy operations via non-tar `copyDirectoryFromPod` when `enableTarCompression` is false. This is a client-side vulnerability affecting Java-based tooling that uses the client library.
- **CVSS:** 2.4 | **Affected:** Kubernetes Java Client (multiple versions) | **Fix:** Apply K8s Java client update
- **Mitigation:** Always use `enableTarCompression: true` when calling `copyDirectoryFromPod`
- **Reference:** <https://nvd.nist.gov/vuln/detail/CVE-2026-15687>

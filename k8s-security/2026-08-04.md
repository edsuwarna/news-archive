## 🔴 CRITICAL

### 1. Langflow IDOR — Arbitrary Data Access & Session Takeover (CVE-2026-55255)
**Source:** [Sysdig Threat Research](https://www.sysdig.com/blog/understanding-langflow-cve-2026-55255-and-why-higher-cvss-vulnerabilities-arent-always-the-most-exploited)< /br>[Cloudsmith Digest](https://cloudsmith.com/blog/cloud-native-digest-july-2026)
A CVSS 9.9 IDOR-style vulnerability in Langflow (an open-source LLM app builder) allows authenticated attackers to replay tokens from other users, effectively taking over sessions and exfiltrating all application data. The first known in-the-wild exploitation was observed in June 2026 by Sysdig TRT, targeting Langflow deployments commonly run inside Kubernetes pods for AI/ML workloads. Attackers can access unauthorized workflows, steal pipeline configurations containing API keys, and escalate within AI agent architectures.
CVSS: 9.9 | Affected: Langflow < 1.9.2 | Fix: Upgrade to v1.9.2+; apply network segmentation between Langflow instances; enforce per-user token scoping

### 2. containerd CRI Plugin — Arbitrary Host Command Execution (CVE-2026-53488)
**Source:** [Red Hat CVE Page](https://access.redhat.com/security/cve/cve-2026-53488)<[GKE Security Bulletin](https://docs.cloud.google.com/kubernetes-engine/security-bulletins)
A critical flaw in the containerd CRI plugin propagates labels from container image configuration (LABEL instructions) directly to runtime containers without validation. An attacker who controls or influences a container image can embed malicious label values that get executed as arbitrary commands on the host node during `containerd` image pull operations. This enables full cluster compromise since every node running containerd is affected.
CVSS: 9.5 | Affected: containerd < 1.7.x / 1.8.x | Fix: Upgrade containerd to patched version; restrict container image sources; implement admission controllers to reject untrusted images

### 3. Langflow Prompt Injection → RCE via Tool Abuse (CVE-2026-33017)
**Source:** [Security Boulevard](https://securityboulevard.com/2026/04/langchain-langflow-litellm-when-ais-foundation-code-becomes-the-attack-surface/)<[Sysdig CTF Jailbreak Research](https://www.sysdig.com/blog/how-attackers-are-jailbreaking-llms-with-ctf-framing-and-how-to-catch-them)
CVE-2026-33017 is a Remote Code Execution vulnerability in Langflow where prompt injection techniques allow attackers to abuse exposed tools and execute arbitrary code through the AI agent platform. Threat actors exploit the lack of sandboxed tool execution to run system commands, deploy cryptominers, and pivot into the underlying Kubernetes pod environment. First observed in-the-wild exploiting exposed AI endpoints with Monero miners deployed via compromised Langflow instances.
CVSS: 9.1 | Affected: Langflow < 1.9.0 | Fix: Upgrade to patched release; isolate Langflow workloads in dedicated namespaces with strict network policies; enforce output sanitization on all tool invocations

### 4. NVIDIA Container Toolkit — Privilege Escalation via CDI Mode (CVE-2025-23266)
**Source:** [Docker Security Announcements](https://docs.docker.com/security/security-announcements/)<[The Hacker News - Kubernetes Coverage](https://thehackernews.com/search/label/Kubernetes)
CVE-2025-23266, codenamed "NVIDIA Scape" by Google Cloud's cloud security team, is a critical privilege escalation vulnerability in the NVIDIA Container Toolkit when operating in CDI (Component Device Interface) mode. The flaw allows processes inside GPU-accelerated containers to escape container isolation and execute code with elevated privileges on the host. This is particularly dangerous for K8s clusters running ML/AI workloads with GPU nodes using NVIDIA container runtime.
CVSS: 9.0 | Affected: NVIDIA Container Toolkit ≤ 1.17.7 | Fix: Upgrade NVIDIA Container Toolkit to latest patched version; consider disabling CDI mode if not required; monitor for abnormal GPU process behavior

### 6. Docker Authorization Bypass via Incomplete Fix (CVE-2026-34040)
**Source:** [The Hacker News](https://thehackernews.com/2026/04/docker-cve-2026-34040-lets-attackers.html)<[Cyera Research](https://www.cyera.com/blog/cyera-research-discovers-docker-authorization-bypass-that-silently-disables-security-policies)
CVE-2026-34040 is an incomplete fix for CVE-2024-41110 (a CVSS 10.0 perfect-score vulnerability), reintroducing a zero-length body bypass in Docker's authorization middleware. Attackers can exploit this to silently disable security policies, bypass RBAC controls, and execute privileged operations on Docker daemon — directly impacting containers orchestrated by Kubernetes. The vulnerability was discovered by Cyera research team and remains active in older Docker releases.

### 7. Ingress-NGINX Configuration Injection — Rewrite Target (CVE-2026-3288)
**Source:** [Kubernetes Official CVE Feed](https://kubernetes.io/docs/reference/issues-security/official-cve-feed/)<[Sysdig Detection Guide](https://www.sysdig.com/blog/detecting-cve-2026-3288-cve-2026-24512-ingress-nginx-configuration-injection-vulnerabilities-for-kubernetes)<[HackerOne Report](https://hackerone.com/reports/2701701)
A high-severity nginx configuration injection vulnerability in ingress-nginx controller allows an attacker to inject arbitrary nginx directives through the `rewrite-target` annotation. When combined with default custom-errors configuration, this can lead to remote code execution, secret extraction, and full cluster compromise. First patched in March 2026 but still widely unpatched in production environments.
CVSS: 8.8 | Affected: ingress-nginx < fixed version (check specific version matrix) | Fix: Upgrade ingress-nginx controller; remove custom-errors configs; restrict ingress resource permissions via RBAC; implement admission webhooks to validate annotations

### 8. Ingress-NGINX Path-Based Configuration Injection (CVE-2026-24512)
**Source:** [Kubernetes Official CVE Feed](https://kubernetes.io/docs/reference/issues-security/official-cve-feed/)<[Tenable](https://www.tenable.com/cve/CVE-2026-24512)<[HexSec Indonesia](https://www.instagram.com/hexsec.id/)
CVE-2026-24512 exploits a vulnerability where the `rules.http.paths.path` field in Ingress resources can be manipulated to inject nginx configuration directives into the controller config map. The bypass circumvents strict-validate-path-type checks, enabling the same class of attacks as CVE-2026-3288 through a different vector. Blast radius includes potential RCE and Kubernetes secret exfiltration.
CVSS: 8.7 | Affected: ingress-nginx < patched release | Fix: Upgrade ingress-nginx controller; tighten RBAC on Ingress resources; deploy OPA/Gatekeeper policies to sanitize path fields; enable strict-path-mode validation

### 12. Linux Kernel nf_tables Local Privilege Escalation (CVE-2026-23111)
**Source:** [Penligent Hacking Labs](https://www.penligent.ai/hackinglabs/cve-2026-23111/)
CVE-2026-23111 is a Linux kernel local privilege escalation bug in `nf_tables`, the kernel subsystem behind `nftables` used extensively for Kubernetes NetworkPolicy enforcement and kube-proxy iptables alternatives. A single-character typo in the kernel code creates a exploitable race condition that allows unprivileged users to escalate to root privileges, directly compromising the node running the Kubernetes kubelet.
CVSS: 7.6 | Affected: Linux kernel with nf_tables module | Fix: Update kernel to patched version; restrict nftables access via AppArmor/SELinux; use kernel-level monitoring for nf_tables syscalls; enforce mandatory access controls on worker nodes

**Source:** [GKE Security Bulletin](https://docs.cloud.google.com/kubernetes-engine/security-bulletins)<[Scouts by Yutori](https://scouts.yutori.com/19be3e34-b234-4b5a-9841-6eb778c920fe)
CVE-2026-46300, nicknamed "Fragnesia," is a Linux kernel container breakout vulnerability affecting Google Kubernetes Engine (GKE) nodes. ### 14. Argo CD ServerSideDiff Information Disclosure (CVE-2026-45737)
**ServerSideDiff feature in Argo CD leaks sensitive Kubernetes Secrets through specially crafted annotations in the GitHub comparison view.**
**Source:** [CISA Bulletins](https://www.cisa.gov/news-events/bulletins/sb26-201)<[Argo CD CVE Tracking](https://pkg.go.dev/vuln/list)
CVE-2026-45737 is a medium-severity information disclosure vulnerability in Argo CD's ServerSideDiff functionality that exposes Kubernetes Secret contents through sensitive annotations when comparing GitOps applications. For organizations using Argo CD as their primary GitOps delivery tool for Kubernetes deployments, this means secrets stored in manifests could be leaked during routine diff operations, potentially exposing database credentials, TLS certificates, and API tokens to anyone with Argo CD read access.
CVSS: 5.9 | Affected: Argo CD < patched version | Fix: Upgrade Argo CD to latest release; restrict Argo CD RBAC permissions; avoid storing secrets in Git manifests; implement external secret management (Vault, External Secrets Operator)

### 17. Go golang.org/x/crypto/ssh RSA Key Parser DoS (CVE-2026-39829)
